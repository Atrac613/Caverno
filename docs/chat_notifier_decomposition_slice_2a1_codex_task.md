# ChatNotifier Decomposition Slice 2a1: Reproducible Turn-Scope Audit

## Task

- Goal: replace the one-off turn-scope review with a checked-in,
  syntax-aware audit and a shared decomposition manifest.
- User-visible behavior: none.
- Non-goals:
  - changing `ChatNotifier` production behavior;
  - enforcing collaborator architecture rules from Slice 2a2;
  - replacing the existing thread-scope ratchet from Slice 2a3;
  - copying the historical estimate of 45 suspect methods into a baseline.

## Implementation Notes

- Add `analyzer: ^10.2.0` as a direct dev dependency and use analyzer ASTs for
  declarations, complete parameter lists, invocations, property accesses, and
  source locations.
- The manifest must use a versioned schema and contain:
  - the historical source revision and notifier library path;
  - one stable record for every original part;
  - stable `id`, `partPath`, `entrypoints`, `status`, and `collaborators`
    fields;
  - collaborator `id`, `path`, and `sizeBudgetKey` fields.
- Initial statuses are:
  - `keep` for `execution_runtime`, `response_finalization`,
    `error_handling`, `turn_exit`, and `cancellation`;
  - `deferred` for `proposal_parsing`, `proposal_option_extraction`,
    `workflow_proposal_parser`, `task_proposal_quality`,
    `terminal_tool_response_policy`, and `task_proposal_parser`;
  - `extracted` for `content_tool_result_format`, with the
    `content-tool-result-formatter` collaborator;
  - `remaining` for the other 31 records.
- Reconstruct historical entrypoints from `b0c19fdb`. Provide a checked command
  that compares the committed manifest with that revision instead of relying
  only on a manually copied list.
- Scan every current part whose status is `remaining`, `partial`, `keep`, or
  `deferred`, plus every collaborator attached to a `partial` or `extracted`
  record.
- Record each ambient read occurrence independently. A method containing a
  turn-scoped accessor must still emit every ambient read found in that method.
- Use a stable read identity based on file, declaration, read kind, and
  occurrence index. Keep line and column as diagnostics, not as identity.
- Record the complete signature, turn-identifying parameters, turn-scoped
  accessors, scanned paths, read vocabulary, and classification assumptions in
  deterministic output.
- The committed baseline must be generated by the audit, sorted
  deterministically, and reviewed from the current tree. Do not seed it from
  the historical estimate.
- Support read-only default execution and explicit baseline regeneration.
  Baseline writes must require a named flag and an explicit output path.
- Do not change production files, notifier budgets, or part declarations.

## Acceptance Criteria

1. The manifest contains exactly 43 unique historical part records and exactly
   the status distribution described above.
2. The historical paths and entrypoints are reproducibly verified against
   `b0c19fdb`.
3. The audit uses complete syntax trees and complete signatures.
4. Every matching ambient read occurrence receives its own deterministic
   record, including methods that also contain a turn-scoped accessor.
5. The audit scans the manifest-selected current parts and extracted or partial
   collaborators, and reports missing or unexpected paths as errors.
6. Repeated runs on an unchanged tree produce byte-identical JSON.
7. A committed baseline is generated from the audit's actual current findings,
   with no copied historical count.
8. Direct tests cover manifest validation, multiline signatures, multiple reads
   of one kind, mixed accessor and ambient reads, collaborator scanning,
   deterministic ordering, and malformed or missing inputs.
9. No production file, notifier part declaration, or size budget changes.
